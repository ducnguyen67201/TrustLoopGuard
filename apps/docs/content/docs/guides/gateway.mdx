---
title: Gateway
description: Route OpenAI-compatible and Anthropic traffic through the same TrustLoopGuard policies as direct SDK events.
---

Gateway is the proxy integration path. Your application keeps using its provider SDK, but changes
the base URL and API key so requests pass through TrustLoopGuard first.

## What you configure

| Resource | Purpose |
|---|---|
| Provider | Stores the provider endpoint, model, and encrypted provider credential. |
| Route | Gives one provider and agent a stable Gateway address. |
| Runtime API key | Authenticates your application to the Gateway route. |

Routes do not have a separate rule set. Every policy enabled for the selected environment and route
agent applies automatically, using the same event service as `POST /v1/events`.

## Set up a route

1. Open **Gateway → Providers** and connect an OpenAI-compatible or Anthropic provider.
2. Create or select the agent whose traffic the route represents.
3. Open **Gateway → Routes** and create a route using that provider and agent.
4. Create a runtime key under **API Keys**.
5. Copy the route-specific example shown below the Routes table.

For DigitalOcean inference, create an OpenAI-compatible provider with:

```text
Base URL: https://inference.do-ai.run
Default model: deepseek-4-flash
```

Store the DigitalOcean model-access key as the provider secret. Applications call TrustLoopGuard
with the TrustLoopGuard runtime key; the provider credential remains server-side.

## OpenAI-compatible client

```ts
import OpenAI from 'openai';

const openai = new OpenAI({
  apiKey: process.env.TLG_API_KEY,
  baseURL: 'https://<server>/v1/gateway/<route_id>/openai',
});

const response = await openai.chat.completions.create({
  model: 'deepseek-4-flash',
  messages: [{ role: 'user', content: userMessage }],
  max_tokens: 512,
});
```

The corresponding raw endpoint is:

```text
POST /v1/gateway/<route_id>/openai/chat/completions
Authorization: Bearer <tl_live_...>
```

## Anthropic client

```ts
import Anthropic from '@anthropic-ai/sdk';

const anthropic = new Anthropic({
  authToken: process.env.TLG_API_KEY,
  baseURL: 'https://<server>/v1/gateway/<route_id>/anthropic',
});

const response = await anthropic.messages.create({
  model: 'claude-3-5-sonnet-latest',
  max_tokens: 512,
  messages: [{ role: 'user', content: userMessage }],
});
```

Use `authToken`, not the provider's `apiKey` option: Gateway runtime calls authenticate with a
TrustLoopGuard bearer key.

## How policies apply

Gateway creates an input event before the provider call and an output event after it. Both go
through the same `execute_event_submission` service as direct event submissions.

| Policy verdict | Gateway behavior |
|---|---|
| Allow | Forwards or returns content unchanged. |
| Rewrite | Uses the policy's safe replacement. |
| Block | Suppresses content; input blocks never call the provider. |
| Escalate | Suppresses content and queues the configured escalation. |

A rewrite without safe replacement text fails closed. Gateway does not issue an extra model call to
regenerate output.

Blocked and escalated responses use the provider's content-filter response shape and include
`X-TrustLoopGuard-Verdict`, `X-TrustLoopGuard-Phase`, `X-TrustLoopGuard-Trace-Id`, and—when
available—`X-TrustLoopGuard-Policy-Id`.

## Streaming

Set `stream: true` normally. No route toggle is required. Gateway buffers the full upstream result,
checks it, then emits guarded provider-native SSE. Tokens are not forwarded before the output policy
decision is complete.

## Spend controls

OpenAI-compatible calls also support hard per-principal budgets. Create a financial policy with
`meter: llm_usage`, configure the exact model's input/output price, and send a positive `max_tokens`
or `max_completion_tokens` value. Gateway atomically reserves the request's maximum cost before the
provider call, then settles the reservation to actual reported usage. If the maximum would exceed
the remaining daily, weekly, or monthly budget, Gateway returns HTTP 429 without contacting the
provider. Unknown pricing returns 503 and an unbounded budgeted request returns 400; both fail
before provider spend.

## Troubleshooting

- **401 Unauthorized** — the `Authorization` header is missing or the TrustLoopGuard runtime key is
  invalid. A provider key cannot authenticate the Gateway route.
- **404 gateway route not found** — the route id in the URL does not match a route in the runtime
  key's workspace.
- **400 provider kind mismatch** — use the `/openai` address for OpenAI-compatible providers and the
  `/anthropic` address for Anthropic providers.
- **400 budget_max_tokens_required** — a matching LLM budget requires a positive `max_tokens` or
  `max_completion_tokens` value.
- **429 budget_exceeded** — the next request's reserved maximum cost is larger than the principal's
  remaining budget.
- **503 pricing_unavailable** — add a trusted workspace price for the exact model before using a
  hard LLM budget.
- **502 Bad Gateway** — the upstream provider failed, timed out, or returned malformed JSON. This is
  not reported as a policy block.
