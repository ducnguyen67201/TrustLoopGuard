TrustLoopGuard is SDK-driven. A feature is considered supported when users can
reach it through the public SDK surface, the HTTP contract, examples, and docs.

## Support Scope

| Surface | Purpose |
| --- | --- |
| HTTP API | Runtime guard checks and dashboard data access. |
| TypeScript SDK | Type-safe integration for TypeScript applications. |
| Python SDK | Type-safe integration for Python applications. |
| Rust SDK | Type-safe integration for Rust applications. |
| Dashboard | Review traces, policies, settings, and team workflows. |
| Examples | Working integrations for common agent runtimes. |

## Integration Rules

- Runtime checks should use the published SDKs or HTTP API.
- Applications should apply the returned decision before delivering agent
  output.
- Secrets belong in environment variables or secret managers.
- Production integrations should log trace ids for audit and support workflows.

## Verification

Use the smallest meaningful smoke test for the integration surface you touched:

```sh
make quickstart
```

Full verification can include SDK examples, policy authoring checks, and
dashboard review of generated traces.
